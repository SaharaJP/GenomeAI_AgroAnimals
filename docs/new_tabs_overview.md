# Обзор новых вкладок интерфейса

**Дата:** 2026-05-09
**Источник:** `web_app/lib/navigation.ts` + `web_app/components/extended/*`
**Аудитория:** оператор фермы / зоотехник / руководитель / QA / админ

Эти вкладки добавлены поверх ядра (Дашборд / Аналитика / Лента событий / Инсайты / Профили) и отвечают за прикладные сценарии по диплому §3.1.6 и операционные процессы фермы.

---

## Операционные

### 🟢 Рабочие списки (`/worklists`)
**Что:** Per-shift очередь задач (доить, осеменять, лечить, проверять, BCS-замер). Группировка по сменам утро/день/вечер; задачи поступают из автогенерации алертов (см. поток `alerts-and-task-workflow` в Pathfinder) и из ручного создания.
**Зачем:** Зоотехник на смене видит конкретный список действий, отмечает выполнение, фиксирует исход (`outcome_status`: done / cancelled / deferred / escalated). Все исходы попадают в `completion_outcomes` для аналитики SLA.
**Источник данных:** `tasks_v1`, `completion_outcomes` (Postgres).

### 🟢 Воспроизводство (`/reproduction`)
**Что:** Календарь осеменения, проверки стельности (preg_check), отёлы. Метрики: % стельности, days-open, conception rate, сервис-период.
**Зачем:** Репродуктолог отслеживает 21-day cycle, выявляет «открытых» коров (>150 DIM без подтверждённой стельности — этот сигнал теперь питает P1-2c health-economic score), планирует AI/быков.
**Источник:** `breedings.json`, `dm_repro_events.csv` (планируется).

### 🟢 Ветеринария (`/vet`)
**Что:** Очереди ветеринарных задач: вакцинация, осмотр, обрезка копыт, диагностика. Включает **withdrawal periods** (дни, в которые молоко нельзя сдавать после обработки).
**Зачем:** Ветеринар видит список животных, требующих внимания сегодня; календарь вакцинации; контроль изоляции и withdrawal period (молоко с антибиотиками не должно попасть в общий бак).
**Источник:** `dm_health_events.csv`, `dm_treatments.csv`.

### 🟢 Лечение (`/treatments`)
**Что:** Активные курсы лечения с расчётом withdrawal-end, протоколы по событиям, история эффективности (recurrent treatment в 60-дневном окне теперь питает P1-2c).
**Зачем:** Контроль соответствия (compliance) — кто получает лечение, до какой даты молоко идёт «в отход», когда можно возвращать в линию.
**Источник:** `dm_treatments.csv`.

## Принятие решений и экономика

### 🟢 Решения (`/decisions`)
**Что:** Лог всех решений по животным (keep/cull/treat/defer) с обоснованием, привязкой к рекомендации (NPV, инсайт, алерт) и автором. Поддерживает аудит-трейл по диплому §3.5.
**Зачем:** Прозрачность («почему 3891 → выбраковка»), reversibility (откат решения), feedback-loop в калибровку моделей.
**Источник:** `dm_decisions.csv`/`decision_log_v2`. Связан с `tasks_v1.linked_decision_id`.
**⚠️ Дизайн:** не соответствует канону — использует `ResourceListPage` обёртку вместо Topbar+MetricCards (см. PATHFINDER-2026-05-09 → backlog redesign).

### 🟢 Экономика (`/economics`)
**Что:** Финансовая сводка по стаду: молоко×цена, корм×цена, вет.затраты, NPV-бенчмарк (агрегат P1-2c расчётов). Сценарный анализ.
**Зачем:** Руководитель видит маржу на корову, ROI решений по выбраковке, сезонные тренды доходности. Конкретные показатели улучшения маржи (от оптимизации SCC, продуктивности и пр.) зависят от базовых данных конкретной фермы и считаются по формулам `docs/target/economics_v2.md`; до получения пилотных данных числовые ориентиры являются целевыми, а не подтверждёнными.
**Источник:** `dm_economics_daily.csv` (планируется), `dm_prices.csv` (отсутствует — investor_v1 не содержит).

## Системные / эксплуатация

### 🟡 Готовность системы (`/readiness`)
**Что:** Чек-лист готовности к pilot rollout: secret-leak gates, Postgres-only profile lockdown, миграции применены, audit retention настроен, support-bundle собирается.
**Зачем:** SRE/DevOps перед раскаткой проверяет, что adult-контур выдержит prod-нагрузку. Соответствует CLAUDE.md §4 7-gate batter (operational rollout gate).
**Источник:** `/api/operability`, `/api/runtime-state`, `/api/production-profile`.
**⚠️ Дизайн:** не соответствует канону — отсутствует topbar, контент в JSON-дампе вместо структурированных Card-секций (см. backlog redesign).

### 🟡 Мониторинг (`/observability`)
**Что:** Real-time runtime state — storage backend, queue depth, активные сессии, последние ошибки, latency p95.
**Зачем:** Дежурный oncall видит снапшот контура без shell-доступа.
**Источник:** `/api/observability`, `/api/queue-runtime`, `/api/metrics-contract`.

### 🟡 Поддержка (`/support`)
**Что:** Сбор support-bundle (`deploy/adult/ops/collect_support_bundle.sh`), поиск по audit-логам, диагностика инцидентов.
**Зачем:** Пользователь сообщает о проблеме → SRE собирает bundle, пересылает Anthropic/dev — без shell-доступа в prod.

### 🟡 Пилот (`/pilot`)
**Что:** Дашборд hot-pilot фермы: мини-сводка KPI, активные алерты, статус прогона.
**Зачем:** Investor demo + пилотный руководитель видят «здоровье» демо-фермы за 1 экран.

### 🟢 Подключения (`/connections`)
**Что:** Импорт CSV/XLSX из доильных систем (DeLaval, Lely, GEA), валидация, превью, коммит.
**Зачем:** Owner-фермы один раз настраивает, дальше — автозагрузка ежедневных надоев.
