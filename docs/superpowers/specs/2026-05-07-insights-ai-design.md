# Design: AI-Generated Insights with Edit/Delete and Settings

**Status:** Approved (brainstorm phase)
**Date:** 2026-05-07
**Owner:** AI assistant + project lead
**Scope:** GenomeAI AgroAnimals — `/insights` surface (web_app + web_cabinet backend)

## 1. Problem

Current `/insights` page (`web_app/app/(protected)/insights/page.tsx`) renders a hardcoded `DEMO_INSIGHTS` constant from `web_app/lib/api/insights.ts` (12 items). The page does not call the backend. The “Настройка инсайтов” button is a placeholder (`toast('Настройка инсайтов — скоро будет доступна')`).

The backend already has the building blocks but they are not connected to the frontend:

- `web_cabinet/ai/background/insight_scanner.py` — Claude-driven AI scanner with demo + live modes; persists to Postgres `scanner_insights`.
- `web_cabinet/ai/endpoints/insights.py` — `POST /api/ai/insights/scan-now` endpoint.
- `web_cabinet/insights_v1.py` — boundary that returns insights from a seeded JSON file (`data/demo/investor_v1/insights_seeded.json`) with in-memory status state.
- `db/.../scanner_insights` table — minimal columns (insight_id, farm_id, title, category, priority, status, generated_at_utc, generator, payload_json).

Two parallel data paths (legacy boundary JSON and AI-scanner Postgres) need to be unified, the frontend rewired to the boundary, and edit/delete + per-user settings added.

## 2. Goals

1. Insights are generated by AI from real farm data, not hardcoded.
2. User can edit textual fields of an insight (title, body, action, recommendations).
3. User can delete an insight (soft delete; not resurrected by AI rescan).
4. User can change AI-scanner behavior via a working “Настройка инсайтов” dialog: minimum severity threshold, enabled categories.
5. Manual “Сканировать сейчас” button on the page header forces an immediate AI scan.
6. Background AI scan continues to run every 6h via existing cron (`run_insight_scanner_for_all_farms`).
7. Single source of truth: `scanner_insights` Postgres table. Frontend has no hardcoded insight list.
8. All seven CI gates from `CLAUDE.md §4` must pass before any “proven” claim.

## 3. Non-Goals

- Reworking notification/insight-bell badge logic.
- Editing AI-controlled fields like `severity`, `category`, `evidence_ids`, `chart_data` (deemed risky for desync with source data — out of scope).
- Insight comments/threading.
- Multi-user concurrent edit conflict UI (last-write-wins is acceptable).
- Migrating existing `insights_v1.py` callers other than the boundary HTTP endpoints.

## 4. Architecture

```
┌─ Frontend (Next.js) ──────────────────────────────┐
│  /insights page                                   │
│   └─ fetch /api/insights              (list)      │
│      /api/insights/[id] PATCH/DELETE  (edit/del)  │
│      /api/insights/[id]/transition    (status)    │
│      /api/insights/scan-now POST      (manual)    │
│      /api/insights/settings GET/PUT   (filters)   │
└──────────────────┬────────────────────────────────┘
                   │ proxy w/ auth-token forward
┌──────────────────▼────────────────────────────────┐
│ Backend FastAPI (web_cabinet)                     │
│  /api/app/v1/insights/*       (boundary, refactor)│
│   └─ insights_v1.py — Postgres-backed CRUD        │
│  /api/app/v1/insights/scan-now (new boundary)     │
│   └─ delegates to insight_scanner.scan_for_new... │
│  /api/ai/insights/scan-now      (kept for cron)   │
└──────────────────┬────────────────────────────────┘
                   │ psycopg2
```

Single source of truth: `scanner_insights`. AI scanner writes there (cron + manual). Boundary CRUD reads/writes there. Frontend reads only via boundary.

## 5. Database Schema

Alembic migration on top of `20260503_10_domain_model_tables`.

### 5.1 Extend `scanner_insights`

```sql
ALTER TABLE scanner_insights ADD COLUMN IF NOT EXISTS severity TEXT;
ALTER TABLE scanner_insights ADD COLUMN IF NOT EXISTS body TEXT;
ALTER TABLE scanner_insights ADD COLUMN IF NOT EXISTS action TEXT;
ALTER TABLE scanner_insights ADD COLUMN IF NOT EXISTS animal_ids JSONB;
ALTER TABLE scanner_insights ADD COLUMN IF NOT EXISTS recommendations JSONB;
ALTER TABLE scanner_insights ADD COLUMN IF NOT EXISTS chart_data JSONB;
ALTER TABLE scanner_insights ADD COLUMN IF NOT EXISTS edited_at TIMESTAMPTZ;
ALTER TABLE scanner_insights ADD COLUMN IF NOT EXISTS edited_by TEXT;
ALTER TABLE scanner_insights ADD COLUMN IF NOT EXISTS deleted_at TIMESTAMPTZ;
CREATE INDEX IF NOT EXISTS scanner_insights_farm_status_idx
  ON scanner_insights (farm_id, status) WHERE deleted_at IS NULL;
```

`payload_json` retained for backward compat and any non-canonical fields. Critical fields denormalized into typed columns.

### 5.2a New `insight_scan_state`

```sql
CREATE TABLE IF NOT EXISTS insight_scan_state (
  farm_id TEXT PRIMARY KEY,
  last_scan_at TIMESTAMPTZ,
  last_skipped_reason TEXT
);
```

Tracks the most recent cron-scan timestamp per farm so the cron token-saver gate (see §6.4) can decide whether new input has arrived since.

### 5.2 New `insight_settings`

```sql
CREATE TABLE IF NOT EXISTS insight_settings (
  user_id TEXT NOT NULL,
  farm_id TEXT NOT NULL,
  min_severity TEXT NOT NULL DEFAULT 'info',
  enabled_categories JSONB NOT NULL DEFAULT '["production","reproduction","health","feeding","welfare","economics"]',
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  PRIMARY KEY (user_id, farm_id)
);
```

Per (user, farm) settings. Default: all categories enabled, minimum severity = info.

### 5.3 One-Shot Demo Seed

`scripts/seed_demo_insights.py` — idempotent (`ON CONFLICT (insight_id) DO NOTHING`). Loads the 12 hardcoded insights currently in `web_app/lib/api/insights.ts` (or, equivalently, `data/demo/investor_v1/insights_seeded.json` which already contains them) into `scanner_insights` with `generator='seed_demo'`.

This runs once during cutover. Afterwards, the scanner cron and manual scan add new insights organically.

## 6. API Surface

All routes return JSON. All frontend routes are thin Next.js proxies that forward auth token to backend.

### 6.1 Backend (`web_cabinet/api_boundary_v1.py`)

| Method | Path | Body / Params | Behavior |
|---|---|---|---|
| GET | `/api/app/v1/insights` | `?status=&category=&severity_min=` | List insights. Query params, when present, override the user’s `insight_settings`; absent params fall back to settings (`enabled_categories`, `min_severity`). Always excludes `deleted_at IS NOT NULL`. |
| GET | `/api/app/v1/insights/{id}` | — | Single insight. 404 if not found OR soft-deleted. |
| PATCH | `/api/app/v1/insights/{id}` | `InsightUpdateRequest` | Edit `title`, `body`, `action`, `recommendations` (all optional). Sets `edited_at=NOW()`, `edited_by=<user>`. 404 if not found OR deleted. |
| DELETE | `/api/app/v1/insights/{id}` | — | Soft delete: `deleted_at=NOW()`, `status='deleted'`. Idempotent (re-delete → 200 no-op). |
| POST | `/api/app/v1/insights/{id}/transition` | `{ status: 'to_check' \| 'to_follow_up' \| 'done' }` | (existing) Status change. |
| POST | `/api/app/v1/insights/scan-now` | `?farm_id=` | Boundary wrapper. Acquires Redis lock `insight_scanner:lock:{farm_id}` (TTL 120s). On lock contention → 409. Calls `scan_for_new_insights(farm_id)`. Returns `{ count: N, insight_ids: [...] }`. |
| GET | `/api/app/v1/insights/settings` | — | Returns caller’s settings (creates default row if none). |
| PUT | `/api/app/v1/insights/settings` | `InsightSettings` | Upserts settings. |

### 6.2 Pydantic Contracts (`packages/contracts/api_boundary_v1.py`)

Extend / add:

- `InsightItem` — add `severity`, `body`, `action`, `animal_ids: list[str]`, `recommendations: list[InsightRecommendation]`, `edited_at: datetime | None`, `edited_by: str | None`.
- `InsightUpdateRequest` (new) — `{ title?: str, body?: str, action?: str, recommendations?: list[InsightRecommendation] }`.
- `InsightSettings` (new) — `{ min_severity: Literal['info','warn','high','urgent'], enabled_categories: list[str] }`.
- `ScanNowResponse` (extend) — `{ count: int, insight_ids: list[str] }`.

### 6.3 Frontend Routes (`web_app/app/api/insights/`)

- `route.ts` (GET) — list
- `[id]/route.ts` (GET, PATCH, DELETE)
- `[id]/transition/route.ts` (POST) — keep existing path or add if missing
- `scan-now/route.ts` (POST) — switch from `/api/ai/insights/scan-now` to `/api/app/v1/insights/scan-now`
- `settings/route.ts` (GET, PUT)

### 6.4 AI Scanner Updates (`insight_scanner.py`)

- Reads `insight_settings` for the target farm before generating: skips disabled categories during prompt construction or post-filters results.
- Soft-deleted insights are still queried in `get_active_insights` so dedup `_dedup_animal_category_7d` doesn’t recreate identical ones (extend SQL: `WHERE status IN ('to_check','to_follow_up','deleted') AND ...` — pull deleted too for dedup window).
- Redis lock added in boundary wrapper, not in scanner itself, so cron path remains untouched.
- **Cron-only token-saver gate** (`run_insight_scanner_for_all_farms`): before calling Claude, check whether there is any new input since the last scan for that farm. Sources of "new input":
  - rows in `timeline_events` with `created_at > last_scan_at`,
  - sensor anomalies returned by `detect_recent_sensor_anomalies` (window since `last_scan_at`),
  - rows in `alerts_v2` with `created_at > last_scan_at`.
  If all three sources are empty, log `insight_scanner skipped: no new inputs farm=...` and return without calling Claude. Persist the gate state in a small new table `insight_scan_state(farm_id, last_scan_at, last_skipped_reason)` (or as a dedicated row in an existing scan-state table if one exists). The gate applies **only to the cron path** (`run_insight_scanner_for_all_farms`); the manual `scan-now` boundary endpoint always runs to honor explicit user intent.

## 7. UI / UX

### 7.1 `/insights` Page

```
┌─ Header ──────────────────────────────────────────────────────┐
│  Инсайты                                                      │
│  Аналитические выводы и рекомендации по стаду                 │
│                       [⚡ Сканировать сейчас]  [⚙ Настройка]  │
└───────────────────────────────────────────────────────────────┘
[К проверке (5)] [В работе (3)] [Закрыто (2)]
┌─ Таблица ──────────────────────────────────────────────────────
│  • [BADGE]  Заголовок ...                Ферма       Дата   ⋮ │
│             Краткое тело...                                    │
└────────────────────────────────────────────────────────────────
```

- “Сканировать сейчас”: disabled while in flight, shows spinner and label “Сканирую данные…”. On success → toast `Найдено N новых инсайтов`, refetch list. On 503 → toast `ИИ недоступен, попробуйте через минуту`. On 409 → toast `Сканирование уже идёт`.
- “⚙ Настройка”: opens `<InsightSettingsDialog>`.
- Row `⋮` menu: **Изменить** / **Удалить**. Click does not navigate to detail; menu is context-only.
- Empty state: `Нет инсайтов в этой категории. AI-сканер запустится в следующий цикл (или нажмите ⚡)`.
- Loading state: skeleton rows.
- Error state: inline retry button + toast.

### 7.2 `/insights/[id]` Detail Page

- Add header buttons **Изменить** (opens `InsightEditDialog`) and **Удалить** (confirm → DELETE → redirect to `/insights`).
- If `edited_at` present, render small badge `Отредактировано <дата>` near title.

### 7.3 New Components

`components/insights/insight-edit-dialog.tsx`:
- Modal with form: `title` (input), `body` (textarea, multiline), `action` (input), `recommendations` (list of `{text, deadline?}` with `+` to add, `×` to remove).
- Buttons: **Сохранить** / **Отмена**. Submit → PATCH; optimistic update of detail + list; on error show inline message and keep dialog open with unsaved values intact.

`components/insights/insight-settings-dialog.tsx`:
- Modal with two sections:
  1. **Порог важности** — radio group: Все / Информационные / Предупреждения / Высокие / Только срочные.
  2. **Категории** — checkboxes: Производство / Воспроизводство / Здоровье / Кормление / Благополучие / Экономика.
- **Сохранить** → PUT `/api/insights/settings` → close + refetch list with new filters.

### 7.4 Existing Components

- `triage-tabs.tsx` — unchanged structure; counts now derived from API list.
- `insight-detail.tsx` — wire to fetch from API instead of static prop.

## 8. Error Handling and Edge Cases

| Case | Behavior |
|---|---|
| Claude API down during scan-now | 503 + `{ error: 'ai_unavailable', retry_after_sec: 60 }`. Toast on UI. |
| Two parallel scan-now invocations | Redis lock; second caller gets 409. UI toast `Сканирование уже идёт`. |
| Edit on deleted insight | 404. UI shows toast and refetches. |
| Settings narrowed → existing insights stay | Settings only filter list view and future scans. Existing rows are not deleted. |
| Cron error | Logged to `genomeai.ai.insight_scanner` logger; does not affect web startup. |
| Cron run with no new inputs | Skipped before calling Claude; `insight_scan_state.last_skipped_reason='no_new_inputs'`; no token spend. Manual `scan-now` ignores this gate. |
| Scanner recreates a soft-deleted insight | Prevented by extending `_deduplicate` to include `deleted_at IS NOT NULL` rows in dedup base. |
| Empty `scanner_insights` post-cutover | UI empty state with manual scan CTA. Seed script ensures non-empty in demo. |

## 11. Risks and Assumptions

- **Postgres availability:** assumed. Per `CLAUDE.md §7`, fail-fast guards already exist.
- **Claude latency:** live mode can take 3–10s. Mitigated by spinner + lock.
- **CI gates may break on schema change:** migration committed independently, run gates before merging code.
- **Legacy callers of `insights_v1.py`:** before removing JSON-loading paths, grep for `_load_demo_insights`, `_demo_seed_path`. Any other callers (e.g., golden tests) must be migrated or kept via shim.
- **Auth context for `edited_by`:** depends on existing FastAPI dependency for current user. If not available cleanly, fall back to `user_id` from JWT claims.
- **Seed script in prod:** for `adult/prod` profile, seeding demo data is wrong. Script must check `GENOMEAI_PROFILE != 'prod'` and refuse otherwise.

## 12. Out-of-Spec Decisions Captured

- “Полный редактор всех полей” rejected — risk of desync with chart_data and evidence.
- Hard delete rejected in favor of soft delete — keeps audit trail and prevents AI re-creation churn.
- Restoration UI (“архив” tab) deferred — soft-delete row still recoverable by direct DB UPDATE if needed; not a v1 user need.
- Auto-scan frequency configuration deferred — kept hardcoded at 6h. Manual scan covers user-driven freshness.
