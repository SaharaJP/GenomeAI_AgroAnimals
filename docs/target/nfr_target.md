# Target NFR (SLA / Performance / Security / Observability)

Дата: 2026-01-30

Документ фиксирует нефункциональные требования (NFR) для Target и может использоваться как критерии приемки.

## 1) Производительность UI

### Время загрузки

При условии, что данные и артефакты уже рассчитаны (web-cabinet только отображает результаты):

- Основные страницы (Upload / QC / Train / Score / Reports / Alerts / Decisions):
  - p50 ≤ 1.5 с
  - p95 ≤ 3.0 с
- Страница "Job" с логом:
  - p95 ≤ 4.0 с при размере лога до 2 МБ

### Ограничения на файлы

- CSV/TSV выгрузки (данные): по умолчанию ≤ 200 МБ на файл.
- Конфиги/маппинги (YAML/JSON): по умолчанию ≤ 5 МБ.

Техническая реализация лимитов в web-cabinet: см. переменные окружения в разделе 5.

## 2) Данные и задержки

Система работает в batch-режиме (on-prem), допустимая "свежесть" данных:

- Регламентное обновление: 1 раз в сутки.
- Допустимая задержка данных (data staleness): ≤ 24 часа.

## 3) SLA пайплайнов (offline-core)

SLA применимы к стандартному прогону на 1 ферме до ~10k животных при типовом объеме testday/health событий.

- Ingest одного датасета: обычно 1–5 минут; верхняя граница ≤ 15 минут.
- QC: обычно 1–3 минуты; верхняя граница ≤ 10 минут.
- Train (MVP ML модель): обычно 3–10 минут; верхняя граница ≤ 20 минут.
- Scoring: обычно 1–5 минут; верхняя граница ≤ 15 минут.
- Report: обычно 1–3 минуты; верхняя граница ≤ 10 минут.

Safety-ограничение: таймаут job (web-cabinet worker) по умолчанию 30 минут.

## 4) Безопасность (on-prem)

Базовые требования:

- Данные хранятся локально на сервере фермы (web storage + artifacts).
- Доступ в web-cabinet только по логину (RBAC).
- Секреты (ключ сессий, пароли) не хардкодим — только через переменные окружения.

Бэкапы:

- Рекомендуемая частота: ежедневно (ночью) + хранение как минимум 7 дней.
- В репозитории уже есть команды:
  - `python -m genomeai backup --artifacts artifacts --web-storage web_cabinet/storage`
  - `python -m genomeai restore --backup <zip> --artifacts artifacts --web-storage web_cabinet/storage`

Шифрование:

- По умолчанию не требуется на уровне приложения (on-prem).
- Если политика требует: использовать шифрование диска/раздела на сервере (LUKS/BitLocker) + защищенное хранение backup-архивов.

## 5) Наблюдаемость

### Healthchecks

- `/healthz` — liveness, всегда 200, если приложение поднято.
- `/readyz` — readiness, 200 только если доступна БД и каталоги доступны для записи; иначе 503.

### Метрики пайплайнов

В web-cabinet доступна минимальная сводка по джобам:

- `/api/observability` — JSON snapshot (uptime, счетчики, p95 длительности, last status).

### Алерты по падениям джобов

Если джоб завершился неуспешно, создается alert типа `ops.job_failed` с ссылкой на лог.

## 6) Настройки (env)

- `GENOMEAI_WEB_MAX_UPLOAD_MB` (default: 200)
- `GENOMEAI_WEB_MAX_MAPPING_MB` (default: 5)
- `GENOMEAI_JOB_TIMEOUT_SEC` (default: 1800)
- `GENOMEAI_WEB_SECRET` — секрет для сессий (обязательно заменить в проде)
