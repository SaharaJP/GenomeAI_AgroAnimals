# Go/No-Go чеклист: переход Offline → Mini‑Web → Web Cabinet

Этот чеклист — критерии готовности команды к следующему этапу миграции.

## 1) Offline → Mini‑Web (go/no-go)

### Go (обязательные)
- [ ] Есть **Pilot Pack** на реальных данных фермы (zip) с `versions.json`.
- [ ] Команда может развернуть `web_cabinet` on‑prem и открыть `/healthz` и `/readyz`.
- [ ] В `artifacts/` корректно отображаются списки `data_version/qc/model/scoring/report`.
- [ ] CLI пайплайн проходит минимум: ingest → qc → train → score → report (fallback) → pack.
- [ ] Импорт Pilot Pack проходит без ошибок:
  - `python -m genomeai import-pack --pack-zip ... --artifacts artifacts`
- [ ] Логи джобов сохраняются и доступны для просмотра.

### No-Go (критические блокеры)
- [ ] В pack отсутствуют ключи в `versions.json`.
- [ ] Импортёр обнаруживает несоответствие sha256 (если `pack_manifest.json` присутствует).
- [ ] Mini‑Web не гарантирует таймауты и может зависать на джобах.
- [ ] Нет стратегии бэкапа (минимум: `genomeai backup`).

## 2) Mini‑Web → Полноценный кабинет (go/no-go)

### Go (обязательные)
- [ ] RBAC роли и матрица прав согласованы и покрывают ключевые сценарии.
- [ ] Audit Log пишет критические события (загрузки, запуски джобов, изменения правил, решения по алертам).
- [ ] Alerts/Tasks работают end‑to‑end (создание → ack/assign → закрытие).
- [ ] Наблюдаемость:
  - [ ] `/metrics` (JSON) показывает счётчики/статусы джобов.
  - [ ] Алерт по падению джоба настроен (хотя бы через внешний скрипт‑скрейпер).
- [ ] Ограничения NFR применяются (upload size, job timeout) и есть тесты.

### No-Go (критические блокеры)
- [ ] Нельзя доказать кто/когда/что сделал (нет аудита) для критичных операций.
- [ ] Нет способа восстановить систему после сбоя диска/БД.
- [ ] Веб начинает “считать” внутри себя, минуя offline-core.

## 3) Минимальный регресс‑набор перед каждым релизом
- `pytest -q` проходит.
- `python -m genomeai smoke` проходит.
- `python -m genomeai smoke-migration` проходит.
