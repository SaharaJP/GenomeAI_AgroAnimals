# T14-02 — шаг 2: structured tool-query filters + RBAC-aware auxiliary sections

## Что сделано
- `copilot_tools.py` расширен до структурированного `ToolQuerySpec`: intent, top_n, farm_id, object_id, alert_id, severity, status, assignee_team, period_hint.
- Вопрос теперь маршрутизируется не только в tool, но и в детерминированный набор фильтров для fact-pack; итоговая выборка становится воспроизводимой и audit-friendly.
- Для tools добавлены config-driven параметры в `configs/copilot/tools_v1.yaml`: `max_rows`, `intent_bonuses`, `extra_section_prefixes`, `intent_section_prefixes`, `section_permissions`.
- `filter_copilot_fact_pack_by_tool()` теперь режет table-rows по фильтрам (`farm_id/status/severity/object_id/...`) и ограничивает результат `top_n`.
- Дополнительные секции (например, `assistant_knowledge.playbooks`) проходят отдельную RBAC-проверку; если прав нет, секция скрывается и попадает в `hidden_section_prefixes`.
- `answer_question_rag()` добавляет в ответ trace строки tool-route/filters и пишет в audit `query_spec`, `visible_section_prefixes`, `hidden_section_prefixes`.

## Почему это локальный рефактор
- Не меняются оффлайн-пайплайны, форматы run-артефактов и граница `web -> offline-core`.
- Изменения сосредоточены в Copilot tool layer и не требуют переписывать существующий strict source-only fact-pack.
- RBAC реализован поверх уже существующей permission-модели web-cabinet.
