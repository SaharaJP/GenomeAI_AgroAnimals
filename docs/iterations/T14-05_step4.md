# T14-05 — Feedback loop, step 4

Дата: 2026-03-10

## Что завершено

- Финализирован слой подготовки feedback к последующему дообучению/калибровке без запуска retrain.
- Добавлен полный `feedback_history` поверх append-only `feedback_events_v1`:
  - `feedback_sequence_no`
  - `feedback_events_count`
  - `previous_decision`
  - `decision_changed_from_previous`
  - `recommendation_first_decision`
  - `recommendation_latest_decision`
  - `recommendation_has_conflict`
- Метрики feedback loop расширены history-aware показателями:
  - `feedback_events_total`
  - `multi_feedback_recommendations_total/rate`
  - `decision_changed_total/rate`
  - `recommendation_history_preview`
- `Feedback Loop` UI доведён до parity с API: добавлены фильтры `data_version/scoring_run/report_version/model_version/feedback_source` и отдельный history preview.
- Export feedback теперь сохраняет два артефакта:
  - `feedback_dataset.csv` — latest label per recommendation
  - `feedback_history.csv` — полная история решений по рекомендациям
- `manifest.json` теперь фиксирует также `history_rows`, `history_dataset_columns` и ссылку на `feedback_history.csv`.

## Ограничения шага

- Это по-прежнему preparation layer для retraining/calibration, а не сам retrain.
- История решений считается по `recommendation_id`; если разные UI/API источники создают разные fallback-id для фактически одной и той же рекомендации, история разойдётся на несколько цепочек.
- `feedback_history.csv` intentionally append-only snapshot и может содержать конфликтующие решения по одной рекомендации; для обучения по умолчанию следует использовать `feedback_dataset.csv` как latest label snapshot, а history — для quality checks / sample selection.
