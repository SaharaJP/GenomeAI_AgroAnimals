# T14-02 — шаг 4: multi-tool Copilot + cross-tool summary + structured tool trace

## Что сделано
- Добавлен deterministic multi-tool plan для Copilot: один вопрос может активировать несколько tools (`query_anomalies`, `query_tasks`, `query_economics`) без LLM function-calling.
- Multi-tool включается только для вопросов, где в тексте явно найдено больше одного intent (`why`, `what_to_do`, `cost`), чтобы не ломать single-tool сценарии из предыдущих шагов.
- Для каждого tool формируется свой `query_spec` и свой intent; порядок выполнения фиксирован и воспроизводим.
- `answer_question_rag()` теперь умеет собирать единый source-only ответ из нескольких tool results: сначала краткий cross-tool итог, затем отдельные детальные секции по каждому домену.
- В `AssistantResponse` добавлено поле `tool_trace` — структурированный trace выбранных tools, intent-ов, фильтров, RBAC и причин отказа.
- Streamlit AI Assistant показывает `tool_trace` в отдельном expander, не смешивая его с текстом ответа.
- Все ответы остаются в guardrails-подходе: только fact-pack, только подтверждённые данные, с источниками и версионностью.

## Почему это локальный рефактор
- Не меняется граница `web-cabinet -> offline-core`: web по-прежнему только вызывает ядро и рендерит результат.
- Не меняются структуры run-артефактов, `copilot_fact_pack` и citation target; добавлен только orchestration-слой поверх уже существующих tools.
- Single-tool сценарии и строгий source-only режим сохранены без изменения контракта для существующих страниц/тестов.
