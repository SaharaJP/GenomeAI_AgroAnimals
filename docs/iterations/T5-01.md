# T5-01 — KPI воспроизводства + worklist

## Цель
Добавить **offline-core** расчёт KPI воспроизводства и генерацию **worklists** (осеменение/диагностика/повтор) с простыми и прозрачными правилами, плюс UI/экспорт в **web-cabinet**.

## Входные данные (Target v2)
Используются канонические таблицы (CSV/PQ):
- `dm_animals` (animal_id, farm_id, status)
- `dm_lactations` (calving_date, lactation_no, lactation_id)
- `dm_repro_events` (event_date, event_type, result)

Если `artifacts/<dv>/canonical` отсутствует — допускается запуск на `data/fixtures/target_v2`.

## KPI (farm-level)
`asof_date` — дата среза.

1) **Days open (avg, open cows)**
- Для каждой коровы: `days_open = asof_date - last_calving_date` если корова **не подтверждена стельной**.
- В агрегат попадают коровы с `DIM >= VWP`.

2) **Days open (avg, pregnant cows)**
- Если есть положительная диагностика: маппим её на **последнее осеменение до диагностики** и считаем `days_open = conception_service_date - last_calving_date`.

3) **Service period (avg)**
- `service_period_days = first_service_date - last_calving_date` (если было осеменение).

4) **Conception rate (lookback N days)**
- В окне `N = lookback_conception_days` считаем:
  - `services_in_window` — количество осеменений
  - `successful_services_in_window` — количество осеменений, у которых есть **положительная** диагностика, связанная с этим осеменением.
- `conception_rate = successful / services`.

5) **Pregnancy rate (lookback M days)**
- Упрощённая формула:
  - `pregnancies_in_window` — число «концепций» (service_date, связанный с positive pregcheck) в окне `M = lookback_pregnancy_rate_days`.
  - `eligible_open_cows` — коровы с `DIM >= VWP` и не подтверждённые стельными.
- `pregnancy_rate = pregnancies / eligible_open_cows`.

## Разбор событий `dm_repro_events`
Правила вынесены в YAML: `configs/repro/repro_rules_v1.yaml`.
- **Осеменение**: `event_type` содержит один из паттернов (insemin|service|ai|...)
- **Диагностика стельности**: `event_type` содержит (preg|diagnosis|pd|ultrasound|...)
- **Результат**: `result` маппится в `pregnant=True/False` по спискам значений.

## Worklists
### 1) Insemination
Условия:
- корова **не стельная**
- `DIM >= VWP`
- нет ни одного осеменения после последнего отёла

Причина: «прошёл VWP, услуг нет».

### 2) Diagnostics
Условия:
- корова **не стельная**
- есть осеменение после отёла
- с момента последнего осеменения прошло `preg_check_due_days`
- после последнего осеменения нет ни одного pregcheck

Причина: «диагностика стельности просрочена».

### 3) Repeat
Условия:
- корова **не стельная**
- есть осеменение после отёла
- (а) есть **отрицательная** диагностика после последнего осеменения
  - `due_date = last_pregcheck_date + repeat_due_days_if_negative`
- ИЛИ (б) нет диагностики слишком долго: `days_since_service >= repeat_due_days_no_check`

### Приоритизация
Приоритет 1..5 (1 — самый высокий) задаётся бинами в YAML.
