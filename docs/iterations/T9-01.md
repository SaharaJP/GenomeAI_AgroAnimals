# T9-01 — Нефункциональные требования (операционка): NFR-контроли

## Цель
Сформировать набор NFR (SLA/производительность/безопасность/наблюдаемость) и реализовать минимальные контролли в коде:

- лимиты размеров (upload/config)
- таймауты запускаемых джобов
- healthchecks
- метрики пайплайнов + алерты по падениям джобов

## Deliverables

- Документ NFR: `docs/target/nfr_target.md`
- NFR-контроли в web-cabinet:
  - лимиты upload/config
  - таймауты jobs
  - health endpoints `/healthz`, `/readyz`
  - endpoint метрик `/api/observability`
  - alert `ops.job_failed` при падении джоба

## Acceptance criteria (как критерии приемки)

1) **Лимиты файлов**
   - При загрузке файла данных > `GENOMEAI_WEB_MAX_UPLOAD_MB` приложение возвращает 413.
   - При загрузке конфига > `GENOMEAI_WEB_MAX_MAPPING_MB` приложение возвращает 413.

2) **Таймаут джобов**
   - При `GENOMEAI_JOB_TIMEOUT_SEC>0` джоб, превышающий таймаут, завершается со статусом `failed` и exit_code=124.

3) **Healthchecks**
   - `GET /healthz` возвращает 200 и строку `ok`.
   - `GET /readyz` возвращает 200 `ready` при доступной sqlite БД и writable каталогах, иначе 503.

4) **Наблюдаемость**
   - `GET /api/observability` возвращает JSON с `uptime_sec` и агрегатами по `jobs`.
   - При падении джоба создается alert `ops.job_failed` в Alert Center v2 (виден в UI /alerts_v2).
