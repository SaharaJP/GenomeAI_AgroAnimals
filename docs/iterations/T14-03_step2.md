# T14-03 — шаг 2: request-for-approval + PDF export + chat bridge

## Что сделано
- Добавлен request-for-approval слой для weekly plans: `approval_requested_at/by/comment` сохраняются в `weekly_plans_v1`, доступны через API/UI и пишутся в audit как `weekly_plan.request_approval`.
- Добавлен deterministic PDF export weekly plan в offline-core: `genomeai.weekly_plan_pdf.generate_weekly_plan_pdf()` сохраняет `weekly_plan.pdf`, `report_meta.json`, `checksums.json` в `artifacts/<data_version>/weekly_plans/<plan_id>/`.
- В web/API появились новые точки: `POST /api/weekly_plans_v1/{plan_id}/request_approval`, `POST /api/weekly_plans_v1/{plan_id}/export_pdf` и UI-аналоги `/weekly_plans/{plan_id}/request_approval`, `/weekly_plans/{plan_id}/export_pdf`.
- Detail-страница weekly plan показывает, кто запросил approval, и даёт кнопку экспортировать/скачать PDF.
- Streamlit Copilot теперь умеет для ответа типа «Сформируй план на неделю» сохранить deterministic draft weekly plan и отправить его на approval без ручного перехода в отдельную форму.

## Почему это локальный рефактор
- Не меняется существующий approve/reject workflow weekly plan и автосоздание задач после approval.
- PDF строится в offline-core; web-cabinet только вызывает экспорт и отдаёт файл.
- Новые поля в БД additive-only и не ломают старые draft/approved записи.
