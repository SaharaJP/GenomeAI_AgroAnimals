# T12-02 — Автоматическая нарезка задач из алертов и проблем QC

## Цели
1) Автосоздание задач при появлении критичных алертов и QC-ошибок (config-driven).
2) Дедупликация: не создавать дубль задачи по одному и тому же объекту/причине.
3) Сквозные ссылки: alert ↔ task ↔ run_id ↔ объект (animal/group/datafile).

## Реализация

### 1) Правила автосоздания (config-driven)
- `configs/workflow_v2/auto_tasking.yaml`
  - `enabled`: включатель.
  - `critical_severities`: какие severity считаем критичными.
  - `force_sources` / `force_prefixes`: принудительно eligible для QC.
  - `fallback_task`: поведение, если нет правила в `configs/tasks_v1/catalog.yaml`.

### 2) Дедупликация задач
- Источник дедупа: `alerts_v2.dedupe_key` (если есть) — это стабильный ключ по объекту/причине.
- Ключ задач:
  - при наличии dedupe_key у алерта: `alertdk:<alert_dedupe_key>|task:<task_type>`
  - fallback: `alert:<alert_id>|task:<task_type>`

### 3) Где запускается авто-нарезка
- `POST /api/alerts_v2/generate?data_version=<dv>`:
  1) offline-core генерирует candidates (QC/ML/business rules)
  2) web-cabinet upsert'ит их в `alerts_v2`
  3) web-cabinet вызывает `auto_create_tasks_from_alerts(...)`
  4) пишет audit:
     - `tasks_v1.auto_create.summary`
     - (опционально, capped) `tasks_v1.auto_create` per task

### 4) Сквозные ссылки
- В `tasks_v1` сохраняются:
  - `related_alert`
  - `object_type/object_id`
  - версии/прогоны: `data_version/qc_run/model_version/scoring_run/report_version`

### 5) UI
- Alert Center v2: показывает связанные задачи по `related_alert`.
- Worklist v1: кнопка deep-link из задачи в алерт.

## Как проверить вручную
1) Создать/импортировать данные → получить `data_version`.
2) Вызвать генерацию алертов:
   - `POST /api/alerts_v2/generate?data_version=<dv>`
3) Убедиться:
   - в ответе есть `auto_tasks.inserted > 0` (при первых критичных алертах)
   - задачи видны в `GET /api/tasks_v1?status=open`
   - у задач заполнены `related_alert` и `data_version`
   - для QC-задач заполнен `qc_run`
