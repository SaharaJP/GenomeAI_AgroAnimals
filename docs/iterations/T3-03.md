# T3-03 — Детектор аномалий сенсоров → Alerts (v1)

## Цели
1) Типы аномалий: провал данных (dropout), выбросы (outlier), дрейф baseline (drift).
2) Пороги и гистерезис для снижения ложных срабатываний.
3) Генерация объяснимых алертов (почему + что сделать) + отображение в UI на графиках.

## Источник данных
Детектор работает по витрине **`cow_day`** (T3-02):
- ключи: `farm_id`, `animal_id`, `date` (daily)
- флаг наблюдаемости: `is_observed_sensors`
- метрики (v1): `activity_steps`, `rumination_min`, `body_temp_c`

Если витрина `cow_day` отсутствует, генератор алертов возвращает пустой список (best-effort).

## Типы аномалий и правила

### 1) Data dropout
**Что считаем:**
- `gap_days = max(date) - last_observed_date` (по `is_observed_sensors=true`).

**Порог (v1):**
- `gap_days >= 2` → алерт `SENSOR.OFFLINE`.

**Дедуп:**
- один открытый алерт на животное: `dedupe_key = SENSOR.OFFLINE|animal|<animal_id>`.

### 2) Outliers (выбросы)
**Бейзлайн:** последние 14 наблюдений (исключая текущий день), минимум 7 значений.
Используем робастную оценку:
- median + MAD
- `z = (x - median) / (1.4826*MAD)`

**Пороги (v1):**
- `abs(z) >= 3.5` и подтверждение 2 дня подряд, либо `abs(z) >= 5.0` за 1 день.

**Маппинг в алерты (v1):**
- temp spike: `SENSOR.TEMP_SPIKE`
- rumination drop: `SENSOR.RUMINATION_DROP`
- activity drop: `SENSOR.ACTIVITY_DROP`

### 3) Baseline drift
**Идея:** сравнение среднего уровня метрики в последнем окне (7 дней) с базовым периодом (предыдущие 21 день).

**Пороги (v1):**
- temperature: `|delta| >= 0.7°C`
- rumination: `|delta_pct| >= 20%`
- activity: `|delta_pct| >= 25%`

**Гистерезис:** подтверждение по **3-дневному** среднему в хвосте (последние 3 дня тоже превышают порог).

**Алерт:** `SENSOR.BASELINE_DRIFT` (если есть в каталоге).

## Как закрывать алерт
Закрытие делается в Alert Center v2:
- `new → acknowledged → resolved` (обязательно указать `reason` при resolve).

Для сенсорных алертов рекомендуемый `reason`:
- "проверили датчик — проблема связи" / "ложное срабатывание" / "подтверждён факт, назначен осмотр".

## Версионирование / трассировка
В алерты прокидывается:
- `data_version` (обязательно)

В `why` пишутся факты: дата, значения, бейзлайн, z-score, gap_days.
