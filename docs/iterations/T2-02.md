# T2-02 — Decision Log v2

Цель итерации: ввести единый формат решений (append-only) с полями трассировки версий и связями с алертами/отчётами, а также UI для просмотра истории.

## 1) Формат записи

Источник правды — таблица `decision_log_v2` в web DB (`web_cabinet/storage/web.db`).

Поля (минимум):
- `decision_id` — UUID (строка)
- `recommendation_id` — (опционально)
- `action` — действие/решение (строка)
- `user_id`, `username`
- `created_at` — UTC ISO
- `reason` — обязательное для некоторых действий (например `alert.resolve`)
- `comment` — (опционально)
- `related_alert` — ссылка на `alerts_v2.alert_id` (опционально)
- `object_type`, `object_id` — объект решения
- `farm_id`, `group_id` — для фильтров (опционально)
- Версии: `data_version`, `qc_run`, `model_version`, `scoring_run`, `report_version`
- `metadata_json` — расширяемый словарь (JSON)

## 2) Append-only гарантия

В SQLite добавлены триггеры, запрещающие UPDATE/DELETE для `decision_log_v2`.

## 3) Интеграция

Alert Center v2 пишет решения автоматически:
- `alert.acknowledge` при переходе `new -> acknowledged`
- `alert.resolve` при `... -> resolved` с обязательным `reason`

Это реализовано внутри `web_cabinet.alerts_v2.acknowledge_alert/resolve_alert`, поэтому работает одинаково из API и Streamlit.

## 4) UI

Streamlit страница **Decision Log v2** показывает список решений и детализацию, с фильтрами по farm/group/object/alert/recommendation/версии.
